# TAPSEAL lot-v1

Version 1.4.0-lots-rc.1 adds deploy mode byte 3 (`lots`). Its wire parameters are profile byte 1 followed by treasury output-index varint; existing common deploy fields, authority output and compact PoW v2 settings remain. The fixed profile requires 8 decimals, supply 2,100,000,000,000,000 atoms (21 million tokens), a Taproot treasury and metadata authority seal. Other supply values/decimals/profiles are invalid. Payloads remain bounded to 80 bytes.

One lot is 100,000,000,000 atoms (1,000 tokens). Public mint payment must be exactly 700*n sats for n=1..10. Public lot claims do not require a proof and must not carry the operator flag or proof. Approved claims must pay exactly 450*n sats for n=1..10, carry the operator flag and a valid owner-bound compact PoW v2 proof, and fit the wallet's confirmed lifetime quota before expiry. Treasury payments of 450 sats require Taproot relay support; deployment probes policy without broadcasting. Existing compact PoW hash derivation, replay checks, canonical-height and proof lifetime requirements apply to discounted claims.

No partial allocation is allowed when supply or quota cannot cover the complete lot count. No approval reserves supply. Used quota never resets on reapproval; a zero quota revokes eligibility. Quotas are whole-lot multiples. Signed owner authority-seal spends control approvals. Allowlist price-phase updates cannot change lot prices. Existing modes and their proof requirements remain unchanged.

`LOT_ACTIVATION_HEIGHT` is a coordinated future protocol cutover, persisted in indexer metadata and published by the Mainnet API as `lot_activation` with supported extension `lot-v1`. A lot deployment before the cutover or with no cutover is invalid. Once persisted, changing the cutover is refused. Existing histories already beyond a newly selected cutover require deliberate reindexing, not silent reinterpretation. Peers compare the cutover. Indexer restarts and reorg undo retain/restore lot balances, registry usage and proof-use records.

The local home runtime discovers the published Mainnet cutover. Transaction service modules are absent from this distribution. Work is opt-in, one proof at a time; this is not Bitcoin mining, independent-node attestation, automatic rewards or a guarantee that supply remains available. Owner approval is permissioned and publicly recorded. The 450-sat price therefore cannot be described as a permissionless reward for simply running a node.

Miner fees, seal-output BTC and any configured platform fee remain separate from token payment. Wallet preview verifies intended mode, quantity, price, owner, treasury and proof settings before explicit signing. Bitcoin signatures protect a signed transaction; hiding UI controls is not access control. An old node lacking this extension is not a valid interpreter for new lot-mode tokens.
